# Previewer 演示与答辩

1. 启动 Mock 服务，打开 entry/src/main/ets/pages/Index.ets 并启用右侧预览器。首次打开请由本人完成 IDE 的信任提示。
2. 广场展示 HTTP 数据。切换“我丢了／我捡到”和类别，搜索不存在的物品查看空状态；清空关键词重新搜索。
3. 点物品卡片进入详情，解释“列表传 ID，详情再请求接口”的过程，展开联系指引，点左上角返回。
4. 打开“统计”，在寻回概览、类别分布、七日趋势之间切换，记录基线总数及寻回率。
5. 返回广场，点“发布”。空表单点下一步观察校验；点击可见的“使用虚构示例”载入演示内容，或自行填写虚构标题、地点及第二步描述后提交。确认自动返回，广场出现新记录。
6. 到“我的”打开刚发布的记录，点击“确认已寻回”，阅读确认框后完成操作。返回时记录应显示已寻回。
7. 再打开统计，核对总数、今日趋势点、对应类别和已寻回数均已更新。示例：从12条、4条寻回变为13条、5条寻回，寻回率从33%变为38%。实际数字随当前数据变化。
8. 通过测试控制接口切换 error 或 slow，返回广场点刷新，展示失败重试或加载提示。恢复 normal 后重试；课堂录屏结束前恢复正常服务。
9. 展示 gitk 的本工程真实阶段提交，以及分层目录和学校报告。

空结果恢复：先切换寻物类型与数码类别，通过Mock的empty模式显示无数据。恢复normal后，点击“清空筛选”，类型、类别和关键词会一并复位并重新请求全部列表。2026年10月24日已实际验证此流程，见截图25、26。详情确认寻回期间，返回操作会等待请求完成，避免返回刷新早于数据落盘。

重点解释：为什么用 ObservedV2/Trace；Param 与 Event 如何形成单向数据流；Navigation 的 pushPath、onReady、pop 与 onPop；generation 如何拦截过期响应；为什么 HTTP 状态码和 JSON 解析都要检查；图表的数值怎样从记录聚合而来。

不要将演示身份说成真实登录认证，不要将 Mock 联系人说成真实师生，不要把自动化没有覆盖的手势说成已验证。课程要求本人独立理解并能答辩；请按课程规定说明工具辅助使用情况。
