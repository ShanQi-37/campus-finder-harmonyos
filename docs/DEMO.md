# 答辩演示路线（第三版）

先启动Mock、打开英文路径工程、运行Index.ets Previewer。首次12条虚构记录、4条已寻回；已有数据时按页面实际数值演示，不假定固定数量。所有联系内容必须为虚构。

1. 广场：切换寻物/招领，类别和状态Select，关键词搜索，切换新旧排序，翻页，清空筛选；说明List、复用卡片与ObservedV2状态。
2. 进入他人的待寻回启事：查看插画、地点、动态记录；收藏后去“我的→我收藏的”核实。未核对前联系内容隐藏。
3. 认领闭环：校园同学打开初始seed-1校园卡→申请认领→虚构示例→提交；回“我的→身份体验”切互助同学→申请中心→我收到的→核实交接并确认寻回。换回申请者查看“我发出的”，状态通过后详情联系可见。已处理的记录可换其他待寻回物品继续，不重置实际数据。
4. 发布：填入虚构示例→保存草稿离开→我的草稿继续填写→补充线索→预览确认→提交；验证草稿1→0。详情中编辑（加载原字段）、撤回（弹窗说明申请取消）、恢复、动态记录。只有本人启事有管理操作。直接确认寻回同样同步状态。
5. 相似线索：本人开放寻物启事→相似线索→查看同类招领候选与理由→打开详情→仍需提交核对，不直接解锁联系指引。已结束或暂无线索时展示空结果。
6. 统计：先看总数、已寻回、待寻回、待核对；切环形、类别、趋势；7/14/30日与分类组合筛选。发布改变总量/类别/对应日期点，认领通过改变寻回数和比例，撤回减少有效总量，恢复还原。
7. 失败恢复：按API文档在本机测试工具切503/empty/slow/malformed，然后界面刷新；展示错误/加载/空数据与重试。结束务必切normal。
8. 展示Gitk真实阶段提交、三个HTTP测试文件结果、学校格式报告。原版截图在screenshots根目录，第二版在screenshots/v2、第三版在screenshots/v3；不要把旧截图说成新界面。

示例按钮是公开可见的演示填充工具，不绕过提交接口，也不代表人工键盘输入测试通过。验证边界见VALIDATION.md。未制作可选录屏，可按上述路线现场演示或由提交者录制。

从广场、统计和我的底部导航切换主入口；在“我的”分别点击待我核对、我的申请、发布草稿，核对入口方向和真实任务数。

## 第四版管理操作

1. 我的校园选择我发布的，点待寻回、已寻回、已撤回；已撤回记录只在本人管理区出现。本人详情可恢复，返回后按原筛选刷新。
2. 待我核对或我的申请默认显示待核对；下拉切换全部、已通过、未通过、已取消，空状态可点查看全部申请。
3. 发布页保存一份虚构草稿，看到舍弃入口；点舍弃后先选继续填写，内容应保留，再确认舍弃，表单恢复空白、草稿数量归零。舍弃会清除该表单未保存编辑，请只使用虚构演示内容。
4. 两处打开同一草稿时，较新保存会改变版本；旧页面舍弃得到冲突提示，需返回重新打开。这个竞态由隔离HTTP回归验证。
