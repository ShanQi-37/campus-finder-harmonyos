# 答辩演示路线（第二版）

先启动Mock、打开英文路径工程、运行Index.ets Previewer。首次12条虚构记录、4条已寻回；已有数据时按页面实际数值演示，不假定固定数量。所有联系内容必须为虚构。

1. 广场：切换寻物/招领，类别和状态Select，关键词搜索，切换新旧排序，翻页，清空筛选；说明List、复用卡片与ObservedV2状态。
2. 进入他人的待寻回启事：查看插画、地点、动态记录；收藏后去“我的→我收藏的”核实。未核对前联系内容隐藏。
3. 认领闭环：校园同学打开初始seed-1校园卡→申请认领→虚构示例→提交；回“我的”切互助同学→申请中心→我收到的→核实交接并确认寻回。换回申请者查看“我发出的”，状态通过后详情联系可见。已处理的记录可换其他待寻回物品继续，不重置实际数据。
4. 发布：填入虚构示例→两步检查→提交。详情中编辑（加载原字段）、撤回（弹窗说明申请取消）、恢复、动态记录。只有本人启事有管理操作。直接确认寻回同样同步状态。
5. 统计：先看总数、已寻回、待寻回、待核对；切环形、类别、趋势；7/14/30日与分类组合筛选。发布改变总量/类别/对应日期点，认领通过改变寻回数和比例，撤回减少有效总量，恢复还原。
6. 失败恢复：按API文档在本机测试工具切503/empty/slow/malformed，然后界面刷新；展示错误/加载/空数据与重试。结束务必切normal。
7. 展示Gitk真实阶段提交、两个HTTP测试文件结果、学校格式报告。原版截图在screenshots根目录，新版在screenshots/v2；不要把旧截图说成新界面。

示例按钮是公开可见的演示填充工具，不绕过提交接口，也不代表人工键盘输入测试通过。验证边界见VALIDATION.md。未制作可选录屏，可按上述路线现场演示或由提交者录制。
